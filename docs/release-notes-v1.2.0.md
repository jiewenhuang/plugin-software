# 软件中心 v1.2.0

本版本改进 MCP 自动化操作的重试、并发编辑和操作前检查。新增 9 个查询工具，现为 **43 个基础工具 + 2 个默认关闭的敏感工具**；已有工具名称和必填参数保持兼容。

## 三项改进

### 1. 创建请求持久化，重复调用不会重复创建

六类创建工具均接受可选 `requestId`（UUID）。同一资源类型下，相同 ID 和相同输入只尝试创建一次；换用不同输入会返回 `IDEMPOTENCY_CONFLICT`。

- 创建回执保存在 Halo 数据库中，跨插件重载及 Halo 进程重启保留。
- 同一请求并发到达时，只有取得写入资格的调用创建资源，其他调用返回原回执或 `OPERATION_IN_PROGRESS`。
- 资源已保存但回执未完成时，可以通过资源上的请求标记恢复回执。
- 资源后来被修改或删除，重放旧请求只返回原创建结果，不覆盖或重建。
- 新增 `get_create_operation`，查询 pending/writing/succeeded/failed/unknown 状态。

回执只保存输入摘要、目标名称和操作状态，不保存输入正文或敏感值。当前不自动清理回执；管理员清理记录或回退数据库会改变防重复保障。无法确认结果的请求保留 unknown，不自动重建。

### 2. 统计刷新不再必然阻止普通编辑

普通读取增加 `editRevision`。普通更新及发布时，除 `expectedVersion` 外传入 `expectedEditRevision`，即可在业务内容未变的情况下接受统计或元数据造成的版本变化。

实际落库仍发生版本冲突时，最多重新读取并重试两次。每次重试重新检查业务内容和引用，不覆盖其他人的业务修改。

只传 `expectedVersion` 时继续严格校验。敏感配置更新和删除仍使用严格版本，不能使用该宽容机制。敏感值不参与普通业务摘要；普通更新保留最新敏感配置。`editRevision` 表示当前内容，不是修改历史序号。

### 3. 发布前看准备情况，删除前看影响

新增 `check_app_publication`、`check_topic_publication` 及六类 `check_*_deletion`。

- `allowed` 表示当前领域规则是否允许操作；`ready` 还要求没有准备度警告。
- 软件发布检查已发布版本、该版本启用的下载源、目标配置及必要 Secret 是否存在；不输出 Secret 名称或值。
- 专题发布检查条目中的软件是否可见。
- 删除检查返回引用数量、最多 20 个名称样本，以及引用是否阻止删除；同时提示保留的专题或关联软件引用。
- 每组下载源或专题条目最多深入检查 200 条，超限会明确提示检查不完整。

预检查是当前快照，不锁定资源，也不改变原有发布规则。它不验证远程文件能否下载或登录、验证码流程能否成功；实际执行仍重新校验。

## 升级与使用

1. 在 Halo Console 上传 `plugin-software-1.2.0.jar`。
2. 等待插件恢复 STARTED，客户端重新获取工具目录。
3. 在 MCP 服务中为已有密钥勾选需要的新增查询工具；新增工具不会自动授权。
4. 自动化创建始终携带稳定的 `requestId`，重试复用同一 ID 和输入；编辑读取最新详情并携带 `expectedEditRevision`。

新增参数均为可选。旧客户端继续可用，但不会自动获得创建去重或容忍统计变更的能力。重放创建返回的是原回执，后续编辑前需要重新读取资源。

最低要求继续为 **Halo 2.26.0**，Java 21。MCP API 固定为 1.0.0，可选插件依赖仍为 MCP Server `>=1.0.0 & <2.0.0`；不嵌入 MCP API/SDK。基础工具不依赖 AI Foundation。

新增内部 Extension `operations.software.jiewen.run/v1alpha1/SoftwareCreateOperation` 及两项引用索引，既有六类业务 GVK、Console API 和业务数据结构保持兼容。内部请求记录未向普通软件角色或匿名用户开放原始资源权限。

完整参数、工具目录和失败处理见 [MCP 接入文档](../dev/mcp.md)。1.1.0 设计背景见 [原实现方案](mcp-integration-plan.md)。
